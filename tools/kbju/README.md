# Расчёт КБЖУ рецептов (на 100 г)

Скрипт считает приблизительное КБЖУ (калории, белки, жиры, углеводы) на 100 г
**сырых ингредиентов** для каждого рецепта и записывает в существующие поля
таблицы `articles`: `calories`, `protein`, `fat`, `carbs`.

Значения — приблизительные: источником КБЖУ каждого ингредиента служит
встроенный справочник по типовым продуктам, количество переводится в граммы
приблизительно (стакан, ложка, шт, по вкусу и т.п.).

Данные берутся напрямую из БД через `docker compose exec postgres psql`.
Скрипт самодостаточен и запускается на хосте (`python3`, только стандартная
библиотека) из корня репозитория.

## Запуск

```bash
# dry-run: статистика, топ-нераспознанных ингредиентов, пример результата
python3 tools/kbju/calc_kbju.py

# записать результат в БД (транзакция + авто-бэкап)
python3 tools/kbju/calc_kbju.py --apply

# пересчитать уже заполненные рецепты
python3 tools/kbju/calc_kbju.py --apply --force
```

## Опции

| Опция    | Что делает                                                              |
|----------|-------------------------------------------------------------------------|
| `--apply`| записывает результат в БД (по умолчанию — только отчёт, dry-run)        |
| `--force`| пересчитывает рецепты, у которых КБЖУ уже заполнено                     |

## Формат записи

- Значения на 100 г, округлены до 1 знака после запятой, разделитель — точка
  (например `"245.3"`), т.к. точка корректно парсится JS (`Number`).
- Нераспознанные ингредиенты и «по вкусу»/«щепотка» считаются с нулевым весом
  и на расчёт не влияют.
- Если у рецепта суммарный вес всех ингредиентов = 0, рецепт пропускается.

## `--apply` (запись в БД)

1. Авто-бэкап перед изменением: `tools/kbju/backups/pre_<timestamp>.sql`
   (`.sql` в `.gitignore`).
2. Транзакция: `UPDATE articles SET calories, protein, fat, carbs` по id.
3. Повторный запуск без `--force` пропускает уже заполненные рецепты.

## Как это работает

- **Нормализация названия**: убираются размеры/способы обработки (средний,
  свежий, вареный, тертый и т.п.), отсекается «или …», «+ …», скобки, «для …»;
  слова сортируются — так «перец болгарский» и «болгарский перец» совпадают.
- **Подбор КБЖУ**: по нормализованному названию ищется самое длинное совпадение
  во встроенном справочнике (`KBJU`).
- **Перевод количества в граммы**: г/кг/мг/мл/л, стакан, столовая/чайная ложка
  (с учётом «с горкой»/«без горки»/«неполный»), шт/долька/зубчик/листик/ломтик,
  банка/пачка/пакет/плитка, дроби («1/2»), смешанные («1 1/2»), диапазоны
  («4-5»), суммы («120 г + 30 г»).
- **Расчёт**: суммируются КБЖУ и вес всех ингредиентов, затем
  `per100 = nutrient_total * 100 / total_weight_g`.

## Нераспознанные ингредиенты

В dry-run выводятся топ-25 нераспознанных названий. Большая часть — заголовки
разделов («Для теста:», «Для начинки:»), у которых нет количества — они корректно
игнорируются. Если найдены реальные продукты, их можно добавить в справочник
`KBJU` в начале скрипта и перезапустить с `--force`.
