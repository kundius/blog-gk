# Конвертер контента рецептов в tiptap-расширения

Скрипт для преобразования сырого HTML рецептов в структуру с кастомными
tiptap-расширениями: маркер ингредиентов `<div data-ingredients="true">`,
пошаговое руководство `<section class="recipe-steps">` и галереи
`<div class="gallery">`. Заодно чинит битые пути картинок (удвоенное расширение
`..jpg..jpg` -> `..jpg`) по `files.filename_disk`.

Данные берутся напрямую из БД через `docker compose exec postgres psql`, поэтому
отдельных дампов не нужно — скрипт самодостаточен. Запускается на хосте (`python3`,
стандартная библиотека, без node/npm) из корня репозитория.

## Запуск

```bash
# все ещё не преобразованные статьи — только отчёт (dry-run)
python3 tools/convert_recipes/convert.py

# конкретные статьи
python3 tools/convert_recipes/convert.py <id1> <id2> ...

# id из файла (по одному на строку)
python3 tools/convert_recipes/convert.py --ids-file list.txt

# записать результат в БД (транзакция + авто-бэкап)
python3 tools/convert_recipes/convert.py <id> --apply

# переконвертировать уже преобразованную статью (исходник — old_content)
python3 tools/convert_recipes/convert.py <id> --apply --force
```

## Опции

| Опция        | Что делает                                                             |
|--------------|------------------------------------------------------------------------|
| `--apply`    | записывает результат в БД (по умолчанию — только отчёт, dry-run)       |
| `--force`    | переконвертирует уже преобразованные (исходник — `old_content`)        |
| `--out FILE` | путь сохранения JSON-результата (по умолчанию `transformed.json` рядом)|
| `--ids-file` | список id статей из файла, по одному на строку                          |

## Выход

- `STATS` — счётчики: `steps` (преобразовано с шагами), `no-steps`, `skip`
  (уже преобразовано / без контента), `error`.
- `WARN` — если в выходе остались неисправленные битые `src`
  (удвоенное расширение или путь не вида `/files/...`) — признак порчи
  исходных данных, которую скрипт не смог починить.
- `--out FILE` — JSON-массив `[[id, content], ...]` преобразованных статей.

## `--apply` (запись в БД)

1. Авто-бэкап перед изменением: `tools/convert_recipes/backups/pre_<timestamp>.sql`
   (`.sql` в `.gitignore`).
2. Транзакция: `old_content` заполняется оригиналом, если пуст, затем
   `content` обновляется преобразованным значением.
3. `old_content` не перезаписывается — это страховка для кнопки
   «Вернуть старую версию» в админке.

## Как это работает

- **hero / intro** (до первого шага) — обычные `<img>` с сохранением атрибутов.
- **шаги** (`1.`, `2.`, ...) — `<div class="recipe-step">`; несколько параграфов
  внутри шага, разбитых картинками, сохраняются (картинки — галереями).
  Для последнего шага накопление отключено: закрывающий текст и итоговые фото
  остаются в хвосте после секции шагов.
- **хвост** (после последнего шага) — простые `<img>` и заголовки в исходном порядке.
