# AGENTS.md

## Проект
- Monorepo: `backend` (NestJS + Prisma), `site` (Next.js), `postgres`, `gateway` (nginx). Docker Compose.
- Рабочий каталог внутри контейнеров backend и site — `/app`.
- На хосте НЕТ Node.js/npm/tsc. Все команды выполняются ТОЛЬКО через `docker compose exec` из корня репозитория.
- Абсолютные пути хоста внутри команд запрещены. Внутри контейнеров используется только `/app`.

## Проверка кода
- Единственный инструмент проверки — компилятор TypeScript. ESLint, Prettier, `npm lint`, `npm format` и любые проверки стиля отсутствуют и НЕ запускаются.

## Тайпчек
- Перед командами убедись, что контейнеры запущены. Если нет — подними их: `docker compose up -d`.
- backend: `docker compose exec backend sh -c "cd /app && ./node_modules/.bin/tsc --noEmit"`
- site: `docker compose exec site sh -c "cd /app && ./node_modules/.bin/tsc --noEmit"`

## Автогенерация
- `backend/src/generated/`, `schema.gql`, `schema.generated.tsx` регенерируются автоматически (watch-режим). Редактировать вручную ЗАПРЕЩЕНО.
- После изменений в исходниках достаточно ОДНОЙ успешной проверки `tsc --noEmit`. Множественные `grep` и циклы по сгенерированным файлам запрещены.

## Тестирование и проверки
- **Поведенческие проверки ЗАПРЕЩЕНЫ.** Не пиши и не запускай E2E, интеграционные или unit-тесты (Jest, Playwright и т.д.). Пользователь проводит поведенческое тестирование самостоятельно.
- Твоя зона ответственности: корректная реализация логики и успешный проход `tsc --noEmit`.

## Миграции Prisma
- Выполняются только через `./run.sh migrate` (dev) и `./run.sh deploy` (prod).
- Существующие файлы в `backend/prisma/migrations/` редактировать ЗАПРЕЩЕНО.

## Запрещенные зоны (не редактировать, не коммитить)
- `src/generated/`, `dist/`, `node_modules/`, `.next/`
- `.env`, `.env.*`
- `backend/prisma/migrations/*` (существующие), `*.tsbuildinfo`
- `*.pgsql`, `*.tar.gz`

## Ограничения и правила работы
- Если команда падает из-за особенностей окружения (нет бинарника, неверный путь) — не пытаться «чинить» более 1 раза. Сразу переходить к тайпчеку или логике задачи.
- Не создавать конфигурационные файлы (eslint, prettier и т.п.) без явного запроса.

## Чек-лист перед коммитом
1. Тайпчек `tsc --noEmit` в нужном контейнере (backend или site).
2. `git status` — убедиться, что запрещенные зоны не затронуты.

## Формат вывода и коммитов
- Показывать только `git diff`, НЕ полные файлы.
- Пояснения — максимум 2-3 предложения.
- Лимит ответа — 2000 токенов.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `refactor:`).
